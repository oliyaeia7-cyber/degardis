# دگردیس (Degardis) — آزمایشگاه فرمت تصویر

سایتی کامل با فرانت‌اند HTML/CSS/JS و بک‌اند Flask (پایتون) که:

1. فرمتِ واقعیِ هر فایل تصویری را از روی **محتوای فایل** (نه فقط پسوند اسمش) تشخیص می‌دهد.
2. فایل را به یکی از فرمت‌های تصویری انتخابی کاربر تبدیل می‌کند («دگردیس» می‌کند).
3. هر ۱۸ فرمت جدول شما را در یک کاتالوگ نشان می‌دهد.
4. یک پنل مدیریت با ورود رمزدار دارد که آمار استفاده از سایت را نشان می‌دهد.
5. سئوی کامل (متا‌تگ، Open Graph، Twitter Card، JSON-LD، robots.txt، sitemap.xml) دارد.

## متغیرهای محیطی (روی Render تنظیم کنید)

| متغیر | توضیح | ضروری؟ |
|---|---|---|
| `ADMIN_PASSWORD` | رمز ورود به پنل مدیریت (`/admin`) | برای استفاده از پنل ادمین بله |
| `SECRET_KEY` | کلید امضای نشست (session) فلسک — بدون این، هر ری‌استارت سرور ورود ادمین را باطل می‌کند | بله (در Render می‌تواند خودکار تولید شود) |
| `SITE_URL` | آدرس نهایی سایت، برای canonical/OG/sitemap (مثلاً `https://degardis.onrender.com`) | توصیه‌شده |

نحوه‌ی تنظیم در Render: داشبورد سرویس → تب **Environment** → **Add Environment Variable**.

## پنل مدیریت

آدرس ورود: `/admin`. بعد از ورود با رمز درست، در `/admin/dashboard` این‌ها دیده می‌شود:

- تعداد کل تشخیص‌ها و تبدیل‌ها از زمان بالا آمدن سرور
- پرتکرارترین فرمت‌های ورودی و خروجی
- وضعیت فعال/غیرفعال بودن افزونه‌های HEIF و AVIF
- فهرست فعالیت‌های اخیر

⚠️ این آمار **درون‌حافظه‌ای** است — با هر ری‌استارت سرور (مثلاً دیپلوی جدید روی Render) صفر می‌شود؛ برای ماندگاری واقعی نیاز به دیتابیس دارد.

## اجرا روی سیستم خودتان

```bash
cd image-format-lab
python3 -m venv venv
source venv/bin/activate        # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
python3 app.py
```

سپس آدرس زیر را در مرورگر باز کنید:

```
http://127.0.0.1:5000
```

## درباره‌ی «تشخیص فرمت»

این موتور یک مدل هوش مصنوعیِ آموزش‌دیده نیست؛ چون فرمت فایل تصویری در چند بایت
اول آن (Magic Bytes / سرآیند فایل) به‌طور قطعی مشخص می‌شود. کد در `app.py`
دو لایه دارد:

- اول با کتابخانه‌ی **Pillow** تلاش می‌کند فایل را باز و اعتبارسنجی کند
  (دقیق‌ترین روش برای فرمت‌های رایج).
- اگر Pillow فرمت را نشناخت (مثل PDF، PSD، XCF، ICNS، HEIC/AVIF بدون افزونه)،
  سراغ تحلیل امضای باینری فایل می‌رود.
- در نهایت اگر هیچ‌کدام جواب نداد، از پسوند نام فایل استفاده می‌کند.

این یعنی حتی اگر پسوند یک فایل را عمداً تغییر دهید (مثلاً یک PNG را به `.jpg`
تغییر نام دهید)، سایت باز هم فرمت واقعیِ آن را درست تشخیص می‌دهد — همان‌طور
که در تست دیده شد.

## سطح پشتیبانی هر فرمت

| سطح | توضیح |
|---|---|
| **تبدیل کامل** | JPEG, PNG, WebP, GIF, BMP, TIFF, ICO, ICNS — به‌صورت کامل با Pillow، بدون نیاز به نصب اضافه |
| **فقط ورودی** | PSD — فقط تصویر ترکیب‌شده (flatten) خوانده می‌شود، بدون لایه‌ها |
| **فقط خروجی** | PDF — تصویر می‌تواند در یک فایل PDF ذخیره شود؛ اما به‌عنوان ورودی فقط شناسایی می‌شود |
| **نیازمند افزونه‌ی اختیاری** | AVIF (نیازمند `pillow-avif-plugin`) و HEIC/HEIF (نیازمند `pillow-heif`) — کد این افزونه‌ها را به‌صورت خودکار در صورت نصب فعال می‌کند |
| **فقط شناسایی** | SVG (برداری)، RAW، DNG، XCF، EPS — این‌ها فقط شناسایی می‌شوند؛ تبدیل واقعی‌شان نیازمند ابزارهای تخصصی جداگانه است (مثل rawpy برای RAW/DNG یا Ghostscript برای EPS) که در این نسخه گنجانده نشده تا سایت به دروغ ادعای پشتیبانیِ کامل نکند |

برای فعال کردن AVIF و HEIC/HEIF به‌صورت کامل، این دو خط را در `requirements.txt`
از حالت کامنت خارج و دوباره نصب کنید:

```
pillow-avif-plugin==1.4.6
pillow-heif==0.18.0
```

## ساختار پروژه

```
image-format-lab/
├── app.py                  # بک‌اند Flask: تشخیص + تبدیل + پنل ادمین + سئو
├── requirements.txt
├── index.html               # صفحه‌ی اصلی
├── admin_login.html         # فرم ورود مدیر
├── admin_dashboard.html     # داشبورد آمار
├── style.css                # طراحی (تم تاریک‌خانه‌ی عکاسی + لهجه‌ی طلایی «دگردیس»)
└── main.js                  # منطق آپلود، تشخیص و تبدیل در مرورگر
```

فایل‌های `robots.txt` و `sitemap.xml` فایل نیستند؛ توسط `app.py` به‌صورت
پویا و بر اساس `SITE_URL` تولید می‌شوند (مسیرهای `/robots.txt` و `/sitemap.xml`).

## امنیت مسیر static

چون همه‌ی فایل‌های پروژه (از جمله `app.py`) کنار هم در ریشه هستند، مسیر
`/static/<file>` فقط اجازه‌ی سرو کردن پسوندهای امن (css، js، تصاویر، فونت) را
می‌دهد؛ درخواست هر فایل دیگری (مثل `.py`، `.txt`، `.md`) با خطای ۴۰۴ رد می‌شود.

## نکات فنی

- حداکثر حجم فایل ورودی ۲۰ مگابایت است (`MAX_CONTENT_LENGTH` در `app.py`).
- فایل آپلودشده موقتاً در حافظه‌ی سرور نگه‌داری می‌شود (کش ساده‌ی درون‌حافظه‌ای)
  تا بین درخواست تشخیص و درخواست تبدیل نیازی به آپلود دوباره نباشد؛ برای محیط
  تولید واقعی بهتر است این کش با Redis یا فایل موقت جایگزین شود.
- تصاویر با شفافیت (RGBA) هنگام تبدیل به فرمت‌های بدون آلفا (JPEG، BMP، PDF)
  به‌صورت خودکار روی زمینه‌ی سفید ترکیب می‌شوند تا خروجی خراب نشود.
- چرخش عکس بر اساس متادیتای EXIF دوربین هنگام تبدیل به‌طور خودکار اصلاح می‌شود.
